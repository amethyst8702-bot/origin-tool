# 원산지 결정기준 위반 위험 탐색 툴

FTA 적용 수입물품의 원산지 검증 대상을 탐색하는 업무 보조 도구입니다.

HS 코드·관련 국가·협정을 입력하면 원산지 결정기준, 세율 차이, 수입 실적, 생산 역량, 공급망 등을 분석합니다. 외부 API와 Gemini를 활용해 공정 시나리오와 검증에 필요한 자료도 제시합니다.

분석 결과는 검증 대상 선별을 지원하는 참고자료이며, 원산지 위반을 확정하는 판정은 아닙니다.

## 사이트

| 구분 | 주소 |
|---|---|
| 기존 사이트 | https://amethyst8702-bot.github.io/fta-check/ |
| 수정본 테스트 사이트 | https://amethyst8702-bot.github.io/origin-tool/ |

## 현재 개발 상태

2026-10-01 기준입니다.

- 기존 공개 화면은 `fta-check-main.zip`의 HTML과 일치합니다.
- 개발 출발점은 `fta-check-priority1.zip`입니다.
- 수정본 테스트 사이트의 페이지가 열리는 것을 확인했습니다.
- 외부 API와 AI를 포함한 전체 기능 검증은 아직 완료되지 않았습니다.
- 다운로드 파일명의 `(1)`, `(2)`는 코드 버전 번호가 아닙니다.

## 주요 기능

- 품목별 원산지 결정기준(PSR) 위험 분석
- 부가가치 및 세율 차이 검토
- 원재료·부품 구성(BOM) 분석
- 생산 역량과 공급망 분석
- 원산지 세탁 위험 탐색
- 위반사례·체크리스트 조회
- 미국 CBP 판례 조회
- Gemini 기반 공정 시나리오 추론
- 종합 보고서 PDF·HTML 저장

## 실행 구조

브라우저가 GitHub Pages에서 화면과 데이터 파일을 불러옵니다.

실시간 통계와 AI 요청은 Google Apps Script(GAS) 웹앱으로 전달됩니다. GAS가 외부 API를 호출하고 결과를 브라우저에 반환합니다.

현재 웹 배포본은 로컬 `proxy.py`를 실행하지 않습니다. API 키는 GAS의 Script Properties에서 관리합니다.

데이터 JS 8개는 현재 코드에서 참조하므로 함께 업로드합니다. `import_volume.js`는 외부 API가 자동으로 대체하지 않습니다.

실제 운영 서버 코드는 별도 GAS 프로젝트에서 관리합니다. 현재 ZIP에는 배포용 `GAS_Code.gs.txt`가 포함되어 있지 않습니다. `_verify.js`를 운영 서버 코드로 간주하지 않습니다.

## GitHub Pages 배포 방법

1. ZIP을 압축 해제합니다.
2. 저장소의 Add file → Upload files에서 압축 안의 파일들을 업로드하고 커밋합니다.
3. `index.html`과 데이터 JS 파일이 저장소 최상위에 있는지 확인합니다.
4. Settings → Pages로 이동합니다.
5. Source에서 Deploy from a branch를 선택합니다.
6. Branch는 `main`, 폴더는 `/ (root)`로 선택하고 Save를 누릅니다.
7. 배포 완료 후 Pages에 표시된 주소로 접속합니다.

ZIP 자체를 업로드하는 방식으로는 웹앱이 실행되지 않습니다.

화면 변경이 보이지 않으면 Ctrl+F5로 새로고침합니다.

## GitHub에서 직접 수정하기

1. Code 탭에서 수정할 파일을 클릭합니다.
2. 연필 아이콘(Edit this file)을 누릅니다.
3. 내용을 수정하거나 새 내용을 붙여넣습니다.
4. Commit changes를 눌러 저장합니다.

파일을 삭제하고 다시 업로드할 필요는 없습니다.

`index.html`을 수정해 커밋하면 Pages가 자동으로 다시 배포됩니다. `README.md`는 GitHub 저장소 첫 화면에 표시되며 웹앱 화면에는 자동 표시되지 않습니다.

## GAS 설정

수정본 `index.html`의 `[DEPLOYMENT SWITCH]` 블록에서 API 연결 설정을 관리합니다.

- `APP_CONFIG.API_BASE`: GAS 웹앱 주소
- `APP_CONFIG.BACKEND_TYPE`: 현재 `gas`
- `APP_CONFIG.API_CONTRACT_VERSION`: 현재 `v2.2`
- `PROXY_BASE`: API 주소를 참조하는 호환용 별칭

기존 GAS를 계속 사용할 때는 파일에 들어 있는 실제 주소를 유지합니다.

GAS의 Script Properties에는 사용하는 기능에 맞게 다음 항목을 설정합니다.

- `GEMINI_KEY`
- `GEMINI_MODEL`
- `COMTRADE_KEY`
- `DATA_GO_KR_KEY`

API 키를 HTML이나 공개 GitHub 저장소에 넣지 않습니다. 로컬용 `config.json`, 키 메모, 설정 백업도 공개 저장소에 업로드하지 않습니다.

기존 사이트와 테스트 사이트가 같은 GAS를 사용하면 API 사용량과 서버 측 저장 기능을 공유합니다.

피드백 전송 주소는 현재 별도 `FEEDBACK_GAS_URL`로 지정되어 있습니다.

## 동작 확인 방법

기존 사이트와 테스트 사이트에 같은 HS·국가·협정 조건을 입력해 비교합니다.

1. 데이터 로드 오류 없이 품목 선택이 가능한지 확인합니다.
2. PSR·세율·수입 실적 등 정적 데이터 결과를 확인합니다.
3. 외부 통계와 AI 분석이 실제 반환되는지 확인합니다.
4. 시연에 사용할 BOM·CBP 등 기능을 확인합니다.
5. PDF·HTML 보고서 저장을 확인합니다.
6. API 실패 시 오류 안내와 사용 가능한 분석 결과가 표시되는지 확인합니다.

페이지가 열린다는 사실만으로 외부 API와 전체 기능이 정상이라고 판단하지 않습니다.

## 확인된 미해결 사항

2026-10-01 코드 검토와 모의 테스트에서 확인한 내용입니다. 원본과 priority1 수정본에 모두 남아 있습니다.

- 연결 확인 요청에 실제 GAS 응답을 기다리지 않고 `ok: true`를 반환하여 서버 연결을 정상으로 잘못 판단할 수 있습니다.
- 요청의 취소 신호가 실제 GAS 호출에 전달되지 않아 취소·제한시간 처리가 의도대로 작동하지 않을 수 있습니다.
- 피드백 주소가 별도로 고정되어 있어 API 주소 하나만 바꿔 모든 기능을 이전할 수는 없습니다.
- 실제 GAS 배포 코드와 첨부 코드의 일치 여부는 아직 확인되지 않았습니다.

다음 작업은 실제 연결 확인, 취소·제한시간 전달, API 주소 관리 통일을 보완하는 것입니다.

## priority1 변경 기록

- API 연결 설정을 `APP_CONFIG`로 정리했습니다.
- 로컬 Python 실행·설정 안내를 웹 배포 환경에 맞게 수정했습니다.
- `AGENTS.md`와 `MIGRATION_NOTES.md`를 추가했습니다.
- 데이터 JS 8개와 기존 검증 파일은 변경하지 않았습니다.

priority1은 설정·안내 정리 단계의 수정본이며, 연결 안정화 완료본은 아닙니다.

이후 변경 때는 날짜·수정 파일·변경 내용·검증 결과를 기록합니다.

## 회사 서버 이전 안내

1. 현재 GAS의 action 기반 요청·응답 JSON 형식을 회사 서버에서 구현합니다.
2. `APP_CONFIG.API_BASE`와 별도 피드백 주소를 변경합니다.
3. 브라우저 연결에 필요한 CORS·인증·접근 권한을 구성합니다.
4. API 키를 회사 서버 환경변수 또는 비밀값 관리 시스템으로 이전합니다.
5. GAS 전용 서비스인 PropertiesService·CacheService·UrlFetchApp 등을 회사 서버 기술에 맞게 교체합니다.
6. 데이터의 의미와 구조를 보존합니다.
7. 이전 전후 동일 입력 조건으로 결과를 비교합니다.

주소 변경만으로 서버 이전이 완료되는 것은 아닙니다.

자세한 개발 원칙과 이전 체크포인트는 `AGENTS.md`와 `MIGRATION_NOTES.md`를 참조합니다.
